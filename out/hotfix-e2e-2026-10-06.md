热更（版本检查→补丁清单→逐文件 diff→整包下载→版本推进→登录界面）已**真实打通**，

## 根因链（4 个缺陷，均已修复）

1. **版本戳跳过热更（用户指出的问题）**
   v9 热更脚本在"exec patch hotfix script"阶段把 `VERSION 1.0.125 → 1.0.128`，
   随后 `patch_mgr.app_version_compare` 走 `client_patch == server_patch` 分支 →
   `no_patch=True` → `use_time 0`，整套下载被跳过（证据：char2/3/4/6 等 9 个 npk 从未下载，
   引擎日志 `Failed to open asset file char2.npk …`）。
   修复：新脚本 `deploy/data/hotfix_startup_v10.py`（=v9 去掉版本戳，其余直连/白名单/页签钩子不变）；
   版本推进改由官方补丁覆盖层完成。

2. **补丁清单 script 项指向错误文件**
   原指向 `15398415/79fc4283…`（15MB 全量包，与 APK 内置 script.npk 完全相同 → 永远不会下载、
   版本永不推进，即历史"更新完成需重启死循环"的真正根因）。
   修复：改指官方 1.0.128 补丁脚本包 `65484/0dd6e606a1a8cdacbda00d85ef59f49f`
   （来源 .\files\netease\h62\Documents\script.npk，2021 官方热更产物，含 12 个覆盖层模块
   与 patch_logic/version.py=1.0.128）。

3. **清单 0hash 自校验**
   客户端 `get_patchlist_data_dict` 会校验 `0hash`（= 去空白 canon dump + len 的 md5；
   实测客户端**不排序** key）。改内容不更新哈希 → "解析更新列表失败"。
   修复：使用既有 `deploy/gen_patchlist.py` 重生成（已验证对原文件字节级复现）。

4. **npk_filelist_md5.txt 为空 `{}`**
   客户端逐文件 diff 时 `npk_patcher._check_file` 会查 `npkfilelist_md5info[fileid]`，
   空表直接 KeyError（实机 `KeyError: 384809306 = 0x16EFB95A = guis/shop/shop.py`）。
   修复：新增生成器 `out/tools/gen_npkfilelist_md5.py`，解析 NXPK 索引（header[20:24]=index_offset，
   条目 28B `IIIIIII`）计算每个块 md5；生成 `deploy/data/npk_filelist_md5.txt`
   （当前含 script 12 条；大 npk 索引为引擎专用布局且与本地逐字节相同不会触发 diff，暂不需要）。
   `deploy/gen_patchlist.py` 已改为读取该真实表。

5. **发布机制**：hotfixserver 对清单/md5 表是**启动时缓存** → 更新文件后必须
   `systemctl restart hs-hotfix`（已按其发布流程执行）。
